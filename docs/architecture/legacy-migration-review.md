# VoxPet 2.0 Legacy 마이그레이션 검토

Phase 1~10 완료 후 main b883426의 전체 `src`/Core tests 및 WPF QA 호출을 검토했다. 이 문서는 [최종 계획](../exec_plans/completed/plan-038-migration-review.md)의 참조 감사이며 삭제를 실행하지 않는다. [Runtime](voxpet-2-runtime.md)과 [패키지 규격](../product/voxpet-package-format.md)을 함께 따른다.

## 판단 기준

정상 App에서 대체됐다는 사실과 지금 파일을 삭제해도 된다는 판단은 구분한다. 저장 DTO/enum 숫자·기존 settings/PNG/imageset/motion/wardrobe/slot 파일·migration·독립 비교 oracle 중 하나라도 필요하면 보존한다. 코드 삭제 제안은 없다.

아래 참조는 전체 C# 파일의 타입 token과 선언 파일 내부 사용, WPF QA를 대조한 것이다. 파일명은 실제 참조 파일의 stem이며 같은 파일의 다른 DTO/직렬화/property/binding 의존도 포함한다. XAML binding 및 member를 통한 간접 참조는 원래 VM/DTO 보존 이유로 별도 판단했다. `Core.Models.CharacterDefinition`과 `Core.Character.CharacterDefinition`은 namespace/alias를 직접 구분했다. 원시 파일/행 근거는 로컬 artifacts/test-results/plan038/legacy-references.json에 보존한다.

## QA 전용 비교 renderer

`LegacyMotionReference`([선언](../../src/VoxPet.App/Views/LegacyMotionReference.cs))는 [RuntimeIntegrationQa](../../src/VoxPet.App/Views/RuntimeIntegrationQa.cs)에서만 생성된다. 정상 MotionSurface 경로의 대체는 RenderFrameDrawing이다. 기존 renderer 대비 픽셀 오차와 garment/표정·손동작 호환성을 독립적으로 비교하는 oracle이므로 현재 삭제하지 않는다.

## 새 Legacy bridge의 역할

LegacyImageSetAdapter/Source, LegacySpriteSheetAdapter/Source는 원본을 native 불변 정의로 변환한다. LegacyCostumeAdapter, LegacyHandMotionSchedulerAdapter, LegacyHandMotionTriggerAdapter, LegacyShortcutAdapter는 기존 저장/입력·재생 API를 공통 모델/engine에 연결한다. LegacySpriteSheetRuntime/LegacyCostumeLayer와 LegacyRenderGeometryProvider는 기존 full-sprite blend·눈물·소품·연결 mesh의 정확한 호환 출력을 Core에서 생성한다. 이 클래스들은 이번 migration에서 만든 현재 bridge이며 삭제 대상이 아니다. 정상 경로는 Main/Coordinator → runtime VM → CharacterRuntime → final frame → renderer다.

AudioAnalyzer/AudioLevelProcessor/AudioSession/CaptureLoop/AudioCaptureService와 calibration, settings/window/tray/single-instance/diagnostics는 캐릭터 engine의 중복 구현이 아니다. 마이크/설정/창 수명 경계로 유지하며 별도 임의 교체/삭제를 하지 않는다.

## 결론과 삭제 조건

ImageSetPlayer의 정상 재생 책임, CharacterAnimator의 motion 구현, HandMotionScheduler의 playback 구현, 이전 직접 renderer의 선택 책임은 새 Runtime/engine으로 대체됐다. 남은 타입/API는 호환 경계 또는 비교 oracle이다. 현재 안전하게 삭제할 Legacy 클래스는 제안하지 않는다.

향후 삭제는 기존 파일/설정 migration과 restart/손상 복구가 필요한지 먼저 확인하고, 독립 baseline으로 oracle을 대체한 뒤 compatibility/Windows/OBS 전체 회귀를 통과한 별도 계획에서만 제안한다. 현재 테스트가 통과했다는 이유만으로 그 테스트가 의존하는 기준 구현을 지우지 않는다.
