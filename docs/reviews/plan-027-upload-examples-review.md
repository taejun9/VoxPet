# plan-027-upload-examples Review

## Summary

QA 후 단일 에이전트 자체 리뷰. 코드 기반 교육용 업로드 예제와 다운로드 전달을 검토했다. 외부 독립 리뷰는 수행하지 않았다. 앱 런타임/오디오/기본 캐릭터를 변경하지 않는다.

## QA

- 실제 Core ImageSet.Validate/ImageSetPlayer/SpriteSheetLayout: 늘보군/펠리 ID별246검사, 총492통과. 팔 중복·숨김과 소매 숨김, 종료 후 idle,4표정×8입×2눈×3의상, 기존 시트 규격 확인.
- 실제 Core 조합 목록으로 그린 액션20프레임과 다운로드용 미리보기의 픽셀이 모두 일치한다.
-512px RGBA 등록 PNG76장, 완성3×2/8×2 시트8장, 미리보기27장. 파일 CRC·투명 여백·압축415,106바이트·디코딩79,691,776바이트로 등록 제한 내이며 JSON은256KiB 이내다.
- ZIP CRC, HTML의 모든 로컬 이미지/안내 링크, Python 구문·문서/자산·diff 검사 통과. 조합 모아보기 직접 시각 검토.
- Downloads 폴더/ZIP116파일은 검증 원본과 byte equality 확인, 기존 파일 덮어쓰기 없음. ZIP3,020,959바이트.
- 앱 코드 변경이 없으므로 Windows GUI·전체 기존 엔진 회귀를 반복하지 않았다. 이전 plan026의 Windows 실행/Core199검사 결과는 별도 기록이다.

## Findings

- 생성 중 잘못된 입 도형의 y 좌표를 발견해 수정했으며, 최종 산출물만 다운로드로 전달했다.
- 팔 교체와 대응 소매 포즈,5템플릿/무기4종·오른쪽 방향,팔 null 숨김,Eye/Mouth 장식 Anchor를 예시로 제공한다. 필요 없는 Effect idle은 완전 투명 PNG로 명시했다.
- JSON2개는 동일한 교육용 그림을 각각 늘보군/펠리 ID에 연결하며 실제 개인 그림으로 오인하지 않도록 HTML/안내에 표시했다.
- 새 조합 JSON, 기존 완성 시트, 업로드하면 안 되는 미리보기를 폴더로 구분했다. 기존 PNG 모드 복귀와 표정 슬롯 저장 절차를 안내했다.
- 개인 캐릭터 PNG를 읽거나 전송하지 않고 기존 자료를 보존한다. Pillow는 optional export 도구에만 필요하다.
- 검토 범위 내 미해결 P1/P2 없음.

## Residual Risk

이번 예제는 제작 규격을 설명하는 도형이며 실제 캐릭터의 미술 품질을 대신하지 않는다. 새 다운로드 묶음의 WPF 등록 UI 자체는 macOS에서 실행하지 않았으며 Core 검증과 동일 엔진의 픽셀 비교로 계약을 확인했다. 실제 사용자 그림으로 교체하면 Canvas·소매·포즈 규격을 다시 검증해야 한다.

## Follow-Ups

검증된 도구·사용 안내·완료 기록을 main에 통합하고 Git 정리 절차를 수행한다.
