# plan-015-expressions-mouth Review

## Summary

늘보군6실제 표정, 음량 입8단계, 기존3열/저장 슬롯 호환을 QA 이후 동일 에이전트가 자체 리뷰했다. 서브에이전트를 실행하지 않았다. 실행 코드9e89a07이며 개인 생성 이미지들은 공개 Git/CI/공용 배포에 포함하지 않는다.

## QA

- macOS SDK10.0.401: locked restore/format/analyzer/Release 경고·오류0, Core132/132. 문서/자산/diff 검사 통과.
- [Windows QA](https://github.com/taejun9/VoxPet/actions/runs/37776428922): 동일 Core132/132·publish·WPF smoke 통과, 고유415검사·실패0. 상세16frozen상태·행열·6표정 가족·8열 인코딩·슬롯 저장 재시작·손상 표정 평상 복구·기본 누락 보존 및 기존3열/수명/단축키/탭 회귀.
- [OBS QA](https://github.com/taejun9/VoxPet/actions/runs/37776428945): WGC green/Chroma Key/native alpha 및 각각7프레임 변화 통과. 기존 BitBlt 유효 프레임 없음 유지.
- 개인 자산: 내장 imagegen의6표정×8입×2눈=96개 고유 프레임. 실제 얼굴 차이/입/깜빡임/몸과 가방을 직접 확인했다.352px 정사각 셀8×2/2816×704 RGBA,16MB 제한·투명 여백·순서/해시와 개인 ZIP18파일·CRC·기존 원본 SHA256 확인.

## Findings

- 해결: 초기 생성본 일부가 기존3×2 배치를 따랐다.16프레임4×4를 목표 이미지로 두고 얼굴만 수정해 재생성했다. 화남의 반복 닫힌 입2개도 imagegen으로 개별 수정했다. 배경 경계의 잔색은 도구로 정리했다.
- 해결: 시트 행 간격이 좁아 단순 고정 경계 추출에 이웃 그림 조각이 포함됐다. 별도 개인 패킹 스크립트에서 완전한 캐릭터 영역을 추출·패딩하고8개 입 순서를 정렬했다. 원본과 초안은 별도 버전명으로 보존했다.
- 입 계약: 상세8열은 유한0~1 연속 MouthOpen을 사용한다.3열은 기존 MouthState와0.2/0.6 계약을 유지하여 기존 PNG/테스트를 깨뜨리지 않는다.8열 셀은512px 이하로 메모리 상한을 두고3열의1024px 지원은 유지했다.
- 표정/저장: 기본 가족을 작업 스레드에서 디코딩/freeze하고 UI에서 한 번에 적용한다. 일부 손상 표정은 평상으로 복구하며 기본 실패는 이전 화면을 보존한다.8열 인코딩/슬롯 재시작은 실제 fixture로 확인했다. 기존 사용자 PNG와 슬롯은 자동 변경하지 않는다.
- 오디오/개인정보: 캡처·PCM·음성 저장/전송을 추가하지 않았다. 표정은 수동 선택하며 음성 감정을 추론하지 않는다. 개인 PNG는 로컬 패키지와 imagegen 제작에만 사용했다.
- 문서: 사용자/배포 안내에6표정/8입/3열 호환/기본 가족/저장한 PNG 우선과 적용 절차를 추가했다. 미해결 기능 결함은 발견하지 않았다.

## Residual Risk

Windows 검증은 합성 자료이며 실제 새 개인 PNG를 CI에 보내 실행 화면을 얻지 않았다. 개인 이미지들은 로컬 계약/시각 검사와 ZIP 검증으로 구분한다. 실제 마이크/권한/물리 DPI·키보드/사용자 OBS·GPU는 기존 미실기 범위다. 생성 프레임은 눈/입/몸의 미세한 픽셀 차이가 있을 수 있다. 저장한3열 PNG는 자동으로8열로 변환하지 않으며 그 시트의 기존 반응을 유지한다.

## Follow-Ups

개인 ZIP을 Windows에서 새 폴더에 풀고 데모/표정 전환/실제 마이크 반응을 확인한다. 이전 저장 PNG가 우선이면 표정 종류를 고르고 내장 표정 사용→슬롯 저장으로 새 늘보군을 선택한다. 실기 결과는 Windows 체크리스트에 기록한다.
